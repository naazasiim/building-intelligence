For one request, run one generation/validation operation and feed its text events to the stream; the returned final result and its stream must describe that same operation, not two independent LLM calls. Stream text pieces from the configured LLM through valid OpenAI-compatible SSE chunks, then send the normal stop and `[DONE]` markers. If the provider fails after text began, emit a final clearly labelled unavailable/error line and still close the stream. Keep the existing model discovery and mode selection.

Preserve the compatible `GenerationResult` confidence extension: validate citations and support after each bounded attempt; use `confidence`, `draft_answer`, `issues`, `attempts`, and `low_confidence_reason` with their existing meanings. A validated answer has `high` confidence. Since Open WebUI cannot retract content already streamed, prefix every unvalidated attempt visibly as `DRAFT — checking evidence`; after a failed final check, close with `DRAFT — low confidence, not the final answer` plus a short reason. Store every failed check and its plain-language detail in `QueryResult.generation`; do not present the draft as a validated answer. If no answer text can be judged, confidence is absent and the result reports the real failure or insufficient-evidence outcome. Do not silently discard useful diagnostic checks or strip invalid citations.

Make the Open WebUI display understandable: stream attempted text, indicate a retry/check when applicable, and finish with confidence and source/check information in a compatible, readable form. Keep `/v1/query` richer for learning inspection. The story must state explicitly that the coding assistant (Claude/Codex) must not test with `curl` or any live HTTP/server calls: it verifies only with the story's offline tests and `ruff`, and leaves the live smoke checks (one supported answer, one deliberately unsupported or invalid-output case, stream shape, auth) to the participant, who tests directly in the Open WebUI interface (not Postman, which would only repeat Story 3.1's checks). Write those checks as participant-run steps with compact expected results (status, outcome, confidence, counts), and have the handover report them as "pending participant" rather than run by the assistant. Do not add agentic behavior, broad test suites, new retrieval modes, or UI plugins. Update the architecture/Open WebUI instructions. After creating the story, report its path only.
